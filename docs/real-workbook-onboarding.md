# Onboarding the real workbook

Do this before anyone relies on scenario results from the real file. Expect some iteration.

## 1. Upload and read the compatibility review

Upload the `.xlsx` and open **Understand this workbook → Administrator detail**. The review has three parts.

### Preflight (blocking)

Any of the following makes the workbook inspect-only until it is addressed:
- external links;
- data connections or Power Query;
- pivots or slicers;
- charts, images or drawings (they would not survive the openpyxl edit);
- embedded objects;
- array formulas or data tables;
- iterative calculation;
- complex named formulas;
- dynamic-array, volatile (`NOW`, `TODAY`, `RAND`, `OFFSET`, `INDIRECT`, …), date or cube functions;
- any function outside the tested set, which is currently `SUM` and `IF`.

### Warnings

Hidden sheets, rows or columns stay hidden and are never sent to the AI. Protected sheets cannot hold editable inputs, and protection is never bypassed. Conditional formatting may not be preserved exactly. Missing stored results are also reported.

### Round trip

The file goes through the editing pipeline (openpyxl load and save, then a LibreOffice recalculation) with no changes. It then checks:
- sheets, visibility, names, tables, number formats, formulas and inputs;
- for **new** formula errors (errors already in the baseline are listed separately);
- that the recalculated results match Excel's stored results, with absolute tolerance `1e-8` and relative `1e-6`.

## 2. If it is blocked by unsupported functions

This is the most likely outcome for a real workbook. For each formula family the workbook needs (for example `ROUND`, `MIN`/`MAX`, `SUMIFS`, `VLOOKUP`, `INDEX`/`MATCH`):

1. Build a small **fixture** workbook that uses the function the way the real file does, including edge cases such as blanks, text, zero and errors. Compute **trusted expected results independently**, by hand or in plain Python, the way `backend/app/demo/model.py` does.
2. Add a test that runs the fixture through the real LibreOffice worker and compares the results (see `backend/tests/test_libreoffice_e2e.py`).
3. Only when it passes, add the function name to `SUPPORTED_FUNCTIONS` in `backend/app/workbook/inspect.py`.

Name scanning remains a heuristic. The round trip on the actual file is what enables editing.

If LibreOffice and Excel disagree on something the workbook depends on, don't work around it silently. Either keep the workbook inspect-only, or plan the native-Excel engine described as the extension point in [architecture.md](architecture.md).

## 3. If stored results are missing

Files written by tools other than Excel often have no cached results, so fidelity can't be verified automatically. An administrator (the owner) must do one of these:
- **Provide trusted reference outputs** with `PUT /api/workbooks/{id}/reference-outputs`, using `{"cells": {"Summary!B6": 460680.0, ...}}`, taken from Excel. They are compared with the recalculation.
- **Confirm the baseline** after checking the recalculated results by hand: the **Confirm baseline results** button, or `POST …/confirm-baseline`.

## 4. Review the map

The suggested fields come from labels next to values and from named ranges. They all start **unconfirmed and not editable**. For each field:
- write a business label and a description,
- set the role (input or output) and the unit,
- for percentages, set value type *percent* (stored as a fraction),
- set a minimum and maximum where they make sense,
- add aliases (the words the user actually says),
- add business rules. For example: "Labor cost means hours × wage × (1 + burden); ask which part before changing 'labor costs'."

Then confirm the fields and mark the true inputs as editable.

Per-row results such as per-product margins belong in an **output table** (`output_tables`), not separate fields. The demo map, generated by `python -m app.demo.generate`, is a worked example.

Every map edit creates a new map version and invalidates pending previews. A restore brings back the map version that belonged to the restored workbook version.

## 5. Verify with the user

Run two or three scenarios the user already knows the answer to, and compare them with Excel on a copy of the workbook. Record the outcome in [test-report.md](test-report.md).
